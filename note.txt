Project: Space Knowledge (CS412 final project), Python 3.14, standard library only.

Design: Broker server (login, inventory, item states) and Universe server (world,
deposits, saved state). The client talks only to the Broker, through Front (token
check). Two threads in one process, joined by a channel that sockets can replace later.

Done: world code (rooms, items, containers, doors, loader), Refusal, Request/Response,
ItemCycle (owned/flight/done for drop and pick), PlayerInventory, ResourceBag,
Parser + Commands (inventory, look, drop, pick, mine), crash recovery (pending
operations, answers remembered by op_id), JSON saves, accounts (PBKDF2), session
tokens, admin console with one-time codes, server key handshake, daily log files,
data/space.json (Earth, Moon, Mars), where/look screen on login.

Run: python -m observatory.app.customer_program   (admin: ...admin_program)
Delete the state/ folder to start a new game.

Conventions: constructors type-check their arguments; refusals are returned as
Refusal objects, not raised; JSON files are written atomically; modules only call
logging.getLogger(__name__).

Known issues: one item id per planet (starting torch is always "torch"); no go
command, so Moon and Mars cannot be reached; broken f-string in check_usable;
saved answers grow forever; an item stays locked after a timeout until restart.

Next: go command, unique item ids, sockets instead of the thread channel.

Rules: explain every piece of code line by line; write the test first; commit after
each step; keep a prompts.md for the AI-use declaration.
